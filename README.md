# 拾光 · Image Studio

无需安装、无需构建的静态生图工作台。可部署到 GitHub Pages，在电脑或手机浏览器打开。前端直接连接用户指定的图片 API，没有中转服务器。

## 发布到 GitHub Pages

1. 新建 GitHub 仓库，把本目录的 `index.html`、`styles.css`、`app.js`、`api.js` 和 `.nojekyll` 上传到仓库根目录。
2. 打开仓库 Settings → Pages。
3. Source 选择 Deploy from a branch，Branch 选择 main，目录选择 / (root)，保存。
4. 部署后打开 Pages 显示的网址，一般是 `https://用户名.github.io/仓库名/`。
5. 点击「API 设置」，填写你自己的 API Key 并保存。需要刷新后保留时，勾选「记住 API Key（仅此浏览器）」。默认服务为 `https://www.kuaiaiapi.com`，模型为 `gpt-image-2.5`。

请只上传本网页目录，不要上传旧项目中的照片、生成记录、密钥或配置备份。此网页目录没有密钥或私人照片。GitHub Pages 页面本身公开，访问者使用自己填写的密钥。

## 本地预览

在本目录运行 `python -m http.server 8765 --bind 127.0.0.1`，打开 `http://127.0.0.1:8765`。不要双击 index.html 使用 file:// 打开，浏览器的模块和存储需要 HTTP 或 HTTPS。

## 默认创作参数

常用比例按 16:9、1:1、3:4、2:3、9:16、3:2 排列，两行三列。对应请求尺寸依次为 2048×1152、2048×2048、1728×2304、1360×2048、1152×2048、2048×1360。默认选择 16:9、高质量、生成 1 张、并发 1。结果卡片显示实际返回尺寸，服务商可能缩小输出。

## 功能

- 默认文生图；拖入、粘贴、选择图片后自动切换为图生图，最多 16 张原图。
- 使用 multipart `image[]` 多图上传，可自定义字段。
- 可选背景、主体外观、风格标签：指定背景后只使用该图作场景参考；默认不追加约束。
- 1–20 张批量创作，1–6 路并发。直接图片响应和 task_id 轮询均支持。
- 自定义模型、尺寸、质量、路径、请求超时、轮询间隔及额外 JSON 参数。
- 大图预览、左右切换、单张重试、复用批次、用结果继续创作。
- 下载原图、复制图片、系统文件分享（取决于浏览器支持），Chrome/Edge 桌面端可选择目录并自动保存。
- 自动保存画面描述、参考原图及其角色、尺寸、质量、数量与并发；刷新或重新打开后恢复草稿。
- 可选记住 API Key；取消勾选并保存会删除浏览器中保存的密钥。
- 「清空草稿」只重置当前创作，不删除生成历史或 API 配置。
- 使用 IndexedDB 在当前浏览器保存历史、参考原图和生成原图。
- 浏览器允许时，可将图片拖到桌面。拖到微信不保证兼容，推荐「复制图片」后粘贴，或下载后发送。

## 数据与浏览器限制

- 默认 API Key 只在当前页面内存中。主动勾选「记住 API Key」后，密钥单独保存在当前网站的 localStorage，刷新或重新打开可恢复；取消勾选并保存或清空密钥并保存即可移除。此保存不是加密保险箱，共用设备请勿勾选。密钥不写入创作草稿或生成历史，也不上传 GitHub。连接检查使用无效测试密钥，不使用真实密钥生成图片。
- API 参数与草稿文字/参数保存在 localStorage；参考原图在独立 IndexedDB 数据库 shiguang-drafts 中，仅在添加、删除或修改图片角色时保存。界面显示保存状态。生成历史仍保存在原有 IndexedDB 数据库 shiguang-studio 中；不同设备、浏览器和网址不会同步。清除浏览器数据可能删除历史，请下载重要图片。
- 生成时，提示词与选中的参考图会发给你配置的 API 服务商；GitHub Pages 只提供网页文件。
- 服务商必须允许网页跨域请求，包括 Authorization 请求头，以及结果图片的跨域读取。不同 API / 图片 CDN 的支持可能不同。
- 页面中填写 API 地址时不要把 `/v1` 重复添加到地址和接口路径。默认地址不带 `/v1`，默认路径带 `/v1`。
- 「停止等待」会中止本地等待并停止后续提交，无法撤销服务端已接受的任务，服务商可能继续计费。超时和刷新后请先查看服务商记录，再决定重试。
- 保持网页打开直到生成完成。手机切换后台可能暂停网页；无后端版本不承诺后台持续运行。
- 静态网页无法像桌面软件一样打开资源管理器指定目录。目录按钮用于浏览器授权选择目录和写入；不支持时提供普通下载。
- 模型与参数是否可用取决于服务商，本页不保证第三方模型名称对应的实际底层模型。

## 验证

真实服务 `https://www.kuaiaiapi.com` 的浏览器跨域访问已验证：使用无效测试密钥，页面成功读取 HTTP 401。该检查确认浏览器能访问接口，不验证余额、成功图片响应或模型可用性。没有使用用户密钥执行付费生成测试。

开发验证：安装 Playwright 后，启动上述本地服务，再运行 `node verify.cjs`。脚本使用已安装的 Microsoft Edge。也可通过 `PLAYWRIGHT_MODULE` 环境变量指定 Playwright 模块路径。测试截图在被 Git 忽略的 `test-results` 目录中。

新增持久化验证：运行 `node verify-persistence.cjs`，检查勾选/取消记住密钥、刷新与重新打开草稿、参考原图字节及角色恢复、删除/清空后不复活、旧历史不受影响、刷新不会自动生成。可设置 `TEST_URL` 验证线上页面；仅使用测试数据和测试密钥，不执行付费生成。

## 手机网络中断与结果恢复

- 错误会区分提交/接收生成结果、查询已有任务、获取原图三个阶段。
- 收到图片地址或任务 ID 后立即保存到当前批次。失败后可用「重新获取图片」继续查询或下载，刷新后仍可恢复，不会再次 POST 生图请求。
- 图片下载先不附带鉴权头，避免签名地址的额外跨域预检；只有同 API 站点返回 401/403 才使用密钥重试。其他图片站点永远不会收到密钥。
- 有图片地址时，可用「打开原图链接」在浏览器单独打开。签名链接可能过期，取决于服务商。
- 如果手机在收到任务 ID 或图片地址之前中断，网页无法推断后台图片地址。请先在服务商后台查看结果；重新生成会提示可能重复计费。
- 旧版失败记录没有保留结果地址，无法自动追溯；有服务商提供的任务 ID 或原图网址时，可用“恢复后台结果”导入。新版会保存已收到的结果定位信息。

验证：`node verify-recovery.cjs` 用模拟断网覆盖图片与异步任务在刷新后恢复、只发送 GET 不重复生成、签名图片不携带密钥、移动预览及结果未知时不自动重试。没有使用真实密钥进行收费生图。

## 2026-11-06：快 AI 文生图异步任务

默认“自动”连接方式：当 API 地址为 https://www.kuaiaiapi.com，且文生图路径仍为 /v1/images/generations 时，改为向 /v1/images/generations/async 提交一次请求。收到 task_id 后立即存入浏览器历史，再 GET /v1/images/tasks/{id} 查询。其他 API、用户自定义路径、图生图保持原接口。可以在高级设置选择直接等待或配置其他异步文生图路径。

真实浏览器验证：gpt-image-2.5，1024×1024，low，异步提交 HTTP 200，438 ms 返回任务 ID，25.8 秒查询到 SUCCESS 与原图链接。只提交了一张测试图片。此结果验证文生图任务流程，不代表图生图异步接口已验证，也不能保证初次提交在所有网络下都能收到 ID。

- 查询失败只自动重试 GET（最多连续三次），不自动重试 POST，不自动回退为直接生成。
- 刷新或重新打开后，已拿到任务信息、上次仍在等待且创建时间不足一天的任务，在密钥可用时自动查询结果；没有提交的其余图片不会自动生成。其他旧任务可手动获取。
- 网络中断且未拿到任务 ID 时显示“结果待确认”；收到任务信息但还没拿到图片时显示“结果待获取”；明确接口错误或服务端 FAILED 状态显示“生成失败”。
- 新增“恢复后台结果”：可粘贴该任务的 task_id 或完整 HTTPS 原图网址，只查询/下载已有结果，不重新生成。普通后台日志编号、请求 request_id、任务 task_id 不是同一种标识，只有服务商查询接口认可的任务 ID 才能取回。
- 连接失败时记录等待秒数、是否收到响应头、浏览器在线及后台状态；这些信息不包含 API Key，不能仅凭 Failed to fetch 判断唯一断线原因。

验证：node verify-async.cjs，覆盖旧配置迁移、异步路由、ID 持久化、刷新只查询已有任务、暂时断网重查、未提交图片不自动重发、手动恢复与错误分类。现有 verify.cjs、verify-persistence.cjs、verify-recovery.cjs 继续覆盖原有功能。
